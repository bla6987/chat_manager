# Chat Manager efficiency audit

Audited commit: `d8b1ad75f441e966083d9a3b96eae4e3a2f82bea`.

Three Sol agents reviewed indexing/cache, embedding/search, and visualization paths. Findings below were checked against current source. No extension source was changed. These are additional opportunities beyond the automatic embedding restoration fix already pushed.

## Priority findings

1. **Unchanged message events rebuild and persist the full active chat.** `src/chat-reader.js:916-952` parses every message, retains embedding state, replaces the entry, increments the index version, writes the complete cached chat, and emits a hydration update without checking for a meaningful change. A synthetic harness invoking the actual functions with 10,000 messages observed two unchanged calls both returning true, replacing the entry, and issuing two cache writes containing 20,000 message records total. IndexedDB was mocked to count payloads; this does not measure disk latency. Add safe change detection before persistence/notifications, then consider event-index-aware updates. Checking only the final message would miss earlier edits and swipes.

2. **An embedding bootstrap with zero work still reclusters unchanged chat vectors.** `src/ui-controller.js:868-877` invokes `recomputeEmbeddingClusters()` for nonincremental runs even when no candidates need work. Panel refresh schedules this path (`1987-1994`). The recomputation searches k=2 through 8 and then runs the chosen k again (`663-693`; `src/semantic-engine.js:611-628`). Cache a signature/version of clustering inputs and reuse labels when vectors and membership have not changed. A bounded actual-engine benchmark with 320 synthetic 192-dimensional vectors measured median 44.63 ms for choosing k and 1.45 ms for the final rerun over five trials. These are synthetic Node timings, not measured browser stalls; the implementation yields between trials of k.

3. **Semantic-map updates can queue obsolete, expensive worker builds.** `src/semantic-map-view.js:405-448` copies the full vector matrix and posts a build for every update. `src/semantic-map-worker.js:34-79` performs each build synchronously; the view discards stale results after computation (`297`), without coalescing queued jobs. If builds take longer than hydration refresh intervals, obsolete matrices and computation can accumulate. Keep one build in flight and one pending latest-state refresh. This is a source-confirmed conditional risk, not a measured live backlog.

4. **Background alternate-swipe batches repeatedly copy the entire pending queue.** `src/ui-controller.js:768-774` uses `Array.from(pendingBackgroundSwipeCandidates.values()).slice(0, batchSize)` for batches of 24. With 10,000 pending candidates, this copies approximately 2.09 million references across 417 snapshots. Consume only the next 24 iterator values. This affects explicit workloads with alternate swipes enabled; the corrected automatic path excludes alternates.

5. **Identical overlapping semantic queries can duplicate embedding-provider requests.** `src/ui-controller.js:3120-3130` stores the query embedding only after awaiting the provider. Two identical requests started before the first finishes both miss the cache; the stale-result guard runs afterward. Cache an in-flight promise by query and remove failed promises. A deferred-provider reproduction of this cache pattern produced two calls for one query and one eventual cache entry. This reproduces the pattern, not the complete browser search function, and made no real provider requests.

6. **A clustering buffer is allocated and written but never read.** `src/semantic-map-worker.js:352,372` creates `dist` during every k-means iteration and assigns distances that are otherwise already consumed through `bestDist`. An in-memory version removing those two lines produced identical serialized full-worker outputs for 100, 1,000, and 2,000 synthetic points. The 2,000-point fixture eliminated 148 allocations totaling 2,368,000 bytes. That is cumulative allocation churn, not peak resident memory. This is the clearest behavior-preserving deletion.

## Other confirmed repeated work

- **Warm index normalization:** `src/chat-reader.js:524-527,776` revisits already-normalized loaded messages on unchanged index builds. The actual-function harness counted 10,000 filename checks for a warm unchanged 10,000-message index. Normalize at intake or track schema normalization once.
- **Repeated branch-prefix comparisons:** `src/chat-reader.js:973-1017,1071-1097` rescans shared prefixes for branch detection and sibling context. With 100 siblings of 2,000 messages, actual-function instrumentation counted 400,000 text property reads on initial detection, another 400,000 on unchanged repeat, and another 400,000 for sibling context. Cache results using relevant content versions; preserve invalidation for edits, swipes, and membership changes.
- **Cache loading delays metadata presentation:** `src/chat-reader.js:694-710` awaits cold cached bodies before the metadata notification later in the build. `src/cache-store.js:65-84` queues all reads and retains their results until transaction completion. Render metadata first and hydrate bodies in bounded batches. Full corpus bodies can still be needed for search and branch features; batching alone does not lower their final retained size.
- **Separate write transaction per hydrated chat:** `src/chat-reader.js:585-587,610-615` and `src/cache-store.js:96-110` could batch writes rather than open one transaction per chat in a 50-chat hydration batch.
- **Semantic-search intermediate results:** `src/ui-controller.js:3135-3194` allocates and sorts variant matches before deduplication and retaining 50 results. Aggregate by the existing deduplication key first while preserving best score and associated filenames, then select the best results.
- **Icicle shared-prefix storage:** `src/icicle-data.js:91-115,181-235` repeats chat membership across prefix nodes and pools vectors over those memberships. Compact membership and cached subtree aggregates could help large branching histories; membership itself supports real navigation/filter features and cannot simply be removed.
- **Lower-priority hot loops:** repeated cosine norms and full sorting of pin neighbors (`src/graph-view.js:598-673`), plus linear day-cell hit tests on every heatmap mouse movement (`src/stats-view.js:362-385`). Cache invariant norms, retain only needed neighbors, and calculate grid coordinates directly if these views prove costly in a live profile.

## Validation boundaries

Audit scripts were run from `/private/tmp/chat-manager-efficiency-audit/`: `noop-updates.mjs`, `branch-counts.mjs`, `validate.mjs`, and `worker-unused-buffer.mjs`. They use actual source where described and bounded synthetic data. No new browser performance recording was made for these additional findings, and no production speedup is claimed. The earlier local browser validation belongs to the already-pushed embedding fix, not this audit.

Recommended order: suppress unchanged update work; skip unchanged clustering; coalesce map builds; consume bounded queue batches; coalesce query requests. The unused worker buffer can be removed independently with its equivalence check.
